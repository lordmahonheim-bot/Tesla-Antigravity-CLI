# SKILL : SPÉCIALISTE DE L'ANALYSE DE DOCUMENT & DE LA DOCUMENTATION

Ce Skill formalise la méthode d'audit de document et de rédaction de rapports d'ingénierie cognitive de l'agent Tesla. Elle garantit une rigueur d'analyse absolue, une clarté immédiate, et un alignement parfait avec la posture de Lord Mahonheim (No-Code, Low-Code, Gouvernance locale, Performance humaine).

## 1. Méthode d'Audit de Document en 5 Étapes

Lorsqu'il doit analyser un document de référence, l'agent applique la séquence d'ingénierie cognitive suivante :

```
    [ DOCUMENT SOURCE ]
             │
             ▼
┌──────────────────────────┐
│ 1. Extraction des Faits  │  --> Identification des concepts, outils et métriques
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│ 2. Cadrage Doctrinal     │  --> Confrontation avec le profil de Lord Mahonheim (No-Code/Low-Code)
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│ 3. Analyse de Substance  │  --> Analyse approfondie ligne par ligne, limites et risques réels
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│ 4. Cas d'Usage Low-Code  │  --> Scénarios d'utilisation sans programmation lourde
└────────────┬─────────────┘
             │
             ▼
┌──────────────────────────┐
│ 5. Synthèse Pédagogique  │  --> Rédaction de la Fiche de Lecture haute-fidélité pour Avalon
└──────────────────────────┘
```

### Étape 1 : Extraction Exhaustive des Faits
*   Répertorier toutes les affirmations clés, outils cités, architectures proposées et limitations sans interprétation précoce.
*   Documenter les chemins de fichiers, les numéros de version et les métriques matérielles mentionnées.

### Étape 2 : Cadrage Doctrinal (Confrontation avec la Mémoire Personnelle)
*   Confronter le document aux fichiers personnels canoniques de Lord Mahonheim ([ABOUT_ME.md](file:///home/lord-mahonheim/bifrost/tesla/memory/ABOUT_ME.md), [MY_COMPANY.md](file:///home/lord-mahonheim/bifrost/tesla/memory/MY_COMPANY.md), [MY_STRATEGIC_STYLE.md](file:///home/lord-mahonheim/bifrost/tesla/memory/MY_STRATEGIC_STYLE.md)).
*   **Alerte Déviation** : Rejeter ou adapter tout concept impliquant du codage pur, du développement de modèles complexes de A à Z ou des architectures cloud opaques. Recadrer vers des solutions de gouvernance locale, d'orchestration ou de configuration de fichiers standards.

### Étape 3 : Analyse de Substance & Critique
*   Vérifier la faisabilité réelle et les limites techniques sur l'environnement MIDGARD/NUMENOR.
*   Identifier les angles morts ou les biais d'optimisme de la solution présentée.

### Étape 4 : Identification des Cas d'Usage Low-Code / No-Code
*   Traduire les concepts abstraits du document en actions directes pour l'utilisateur profane.
*   Privilégier l'utilisation d'outils CLI existants, d'APIs standards (OpenAI/Gemini) et de fichiers de configuration structurés plutôt que de développer du code Python ou C++ sur mesure.

### Étape 5 : Rédaction de la Fiche de Lecture (Modèle Haute-Fidélité)
*   Produire un rapport respectant le format canonique : `Diagnostic -> Faits -> Raisonnement -> Hypothèses -> Points Critiques -> Options -> Recommandations -> Plan d'Action -> Preuve`.
