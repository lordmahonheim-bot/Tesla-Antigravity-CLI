1. QU'EST-CE QU'OBSIDIAN ?
--------------------------------------------------------------------------------
Obsidian est une application de prise de notes et de gestion des connaissances
personnelles (PKM — Personal Knowledge Management) reposant sur trois principes
fondamentaux :

  • LOCAL-FIRST : Vos notes sont stockées localement sur votre appareil sous
    forme de fichiers texte simples (Markdown, .md). Aucune dépendance à un
    cloud propriétaire. Vos données vous appartiennent totalement.

  • MARKDOWN-BASED : Toutes les notes sont écrites en Markdown, un format
    texte universel, portable et pérenne. Vous pouvez les lire, éditer et
    exporter avec n'importe quel éditeur de texte, aujourd'hui et dans 50 ans.

  • LIEN BIDIRECTIONNEL : Obsidian traite vos notes comme un wiki
    hyperlié. Chaque note peut pointer vers d'autres notes, et Obsidian
    calcule automatiquement les backlinks (rétroliens), créant un graphe
    de connaissances.

Métaphore : « Si Notion est l'influenceur productivité avec un ring light,
Obsidian est le développeur backend en hoodie qui a construit son propre OS
en silence. » (ps11.hashnode.dev)

Fonctionnalités clés :
  - Édition Markdown temps réel (Live Preview / Reading / Source)
  - Recherche full-text du vault entier
  - Vue graphique (Graph View) — visualisation en réseau de vos notes
  - Système de plugins extensible (2000+ plugins communautaires)
  - Thèmes personnalisables (CSS)
  - Mode hors-ligne total
  - Multi-plateforme : Windows, macOS, Linux, iOS, Android
  - Gratuit pour un usage personnel

Modèle économique :
  - Usage personnel : GRATUIT (toutes les fonctionnalités locales)
  - Obsidian Sync : payant (synchronisation officielle chiffrée E2E)
  - Obsidian Publish : payant (publication web de vos notes)
  - Licence commerciale : payante (usage professionnel)


2. LE CONCEPT DE SECOND CERVEAU (SECOND BRAIN)
--------------------------------------------------------------------------------
Le terme « Second Brain » (Second Cerveau) a été popularisé par Tiago Forte
dans son livre "Building a Second Brain" (BASB). Il désigne :

  « Une méthodologie pour délester votre esprit en externalisant vos idées,
    tâches, connaissances et apprentissages dans un système externe fiable,
    afin que votre cerveau biologique puisse respirer et se concentrer sur
    la pensée créative plutôt que sur la mémorisation. »

Objectifs d'un Second Cerveau :
  1. CAPTURER — Ne plus perdre une idée, une information, un extrait.
  2. ORGANISER — Retrouver instantanément ce dont vous avez besoin.
  3. DISTILLER — Résumer et synthétiser pour ancrer la compréhension.
  4. EXPRIMER — Produire du contenu (articles, décisions, code, projets).

Ces quatre étapes forment la méthode CODE de Tiago Forte :
  C — Capture
  O — Organize
  D — Distill
  E — Express

Un Second Cerveau bien construit :
  • Se souvient à votre place des choses que vous avez lues, entendues, vues.
  • Fait émerger des connexions inattendues entre des idées éloignées.
  • Vous fait gagner un temps considérable lors de la production de contenu.
  • Réduit l'anxiété liée à la peur d'oublier.
  • Devient plus organisé au fur et à mesure qu'il grossit (contre-intuitif).


3. POURQUOI CHOISIR OBSIDIAN POUR SON SECOND CERVEAU ?
--------------------------------------------------------------------------------
Comparaison Obsidian vs Notion (basée sur les retours d'utilisateurs vérifiés) :

  CRITÈRE                    OBSIDIAN               NOTION
  ------------------------   --------------------   -----------------------
  Propriété des données      Locale (100%)          Cloud propriétaire
  Format                     Markdown standard      Format propriétaire
  Fonctionnement offline     Complet                Limité
  Vitesse                    Très rapide            Ralentit avec la taille
  Personnalisation           Plugins + CSS          Limitée
  Versioning                 Git (illimité)         Undo basique
  Coût pour usage personnel  Gratuit                Freemium
  Prise en main              Courbe moyenne         Immédiate
  Écosystème                 Communauté active      Templates officiels
  Adapté aux développeurs    Excellent              Correct

Raison philosophique fondamentale :
  Vos notes personnelles sont l'extension de votre pensée. Elles doivent
  vivre dans un format ouvert et local, sur des fichiers que vous
  contrôlerez toute votre vie. Obsidian est le seul outil grand public
  à respecter cette contrainte de portabilité totale.


4. PRÉREQUIS MATÉRIELS ET LOGICIELS
--------------------------------------------------------------------------------
Configuration minimale recommandée :
  • Windows 10+ / macOS 10.15+ / Linux (AppImage, Flatpak, Snap, .deb, .rpm)
  • iOS 15+ / Android 8+
  • RAM : 4 Go minimum, 8 Go confortable (au-delà de 10 000 notes)
  • Stockage : négligeable pour les notes texte ; prévoir pour les pièces
    jointes (images, PDF, audio, vidéo)
  • Connexion internet : optionnelle (uniquement pour Sync, plugins,
    téléchargements)

Compétences préalables : AUCUNE. La syntaxe Markdown s'apprend en 30 minutes.

Attitudes utiles :
  • Curiosité (pour explorer les plugins et fonctionnalités)
  • Patience (les bénéfices d'un second cerveau sont exponentiels dans le temps)
  • Discipline légère (30 secondes par jour suffisent pour maintenir l'habitude)

5. INSTALLATION MULTI-PLATEFORME
--------------------------------------------------------------------------------
ÉTAPE 1 : Téléchargement
  • Rendez-vous sur https://obsidian.md/download
  • Choisissez la version correspondant à votre système
  • Vérifiez la signature du binaire pour la sécurité (recommandé)

ÉTAPE 2 : Installation
  • Windows : exécuter l'installateur .exe (choisir "Install for me only"
    pour éviter les problèmes de droits admin)
  • macOS : glisser Obsidian.app dans /Applications
  • Linux (AppImage) : rendre l'AppImage exécutable puis lancer
  • Mobile : installer depuis App Store / Google Play

ÉTAPE 3 : Mise à jour de l'installateur
  Obsidian se compose de deux couches :
    - L'application (installeur)
    - Le runtime (mis à jour automatiquement)
  Il est recommandé de mettre à jour périodiquement l'installateur via
  le site officiel (Settings > About > Check for updates).


6. CRÉER ET CONFIGURER UN VAULT (COFFRE)
--------------------------------------------------------------------------------
Le VAULT (Coffre) est un dossier de votre système de fichiers qui contient
toutes vos notes Markdown et pièces jointes. Obsidian ne fait qu'afficher
et manipuler ce dossier — vous pouvez y accéder directement avec
l'Explorateur Windows ou le Finder macOS.

Bonnes pratiques pour créer un vault :
  1. Choisir un emplacement STABLE et facile à sauvegarder
     (ex : ~/Documents/ObsidianVault ou ~/Second-Brain)
  2. Éviter les dossiers synchronisés en temps réel par plusieurs clouds
     (risque de conflits de fichiers)
  3. Utiliser un nom de dossier simple sans espaces ni caractères spéciaux
  4. Créer un vault distinct par grand contexte (personnel, professionnel,
     projet spécifique) — recommandation de Kevin T'Syen

Structure minimale au démarrage :
  MonSecondCerveau/
    ├── .obsidian/          (créé automatiquement, contient la config)
    ├── 00-Inbox/           (capture rapide)
    ├── Templates/          (modèles de notes)
    ├── Attachments/        (images, PDF, médias)
    └── Bienvenue.md        (première note d'accueil)


7. INTERFACE UTILISATEUR : ANATOMIE COMPLÈTE
--------------------------------------------------------------------------------
L'interface d'Obsidian est composée de plusieurs zones :

  A) VOLET GAUCHE
     - Explorateur de fichiers (arborescence du vault)
     - Recherche
     - Bookmarks (favoris)
     - Tags
     - Graphe local
     - Notes récentes

  B) ZONE CENTRALE
     - Onglets de notes ouvertes
     - Éditeur (mode Live Preview / Reading / Source)
     - Barre d'onglets empilables

  C) VOLET DROIT
     - Backlinks (liens entrants)
     - Outgoing links (liens sortants)
     - Outline (plan de la note)
     - Vue graphique globale

  D) RUBAN LATÉRAL (Ribbon)
     - Icônes des commandes fréquentes

  E) BARRE DE STATUT
     - Nombre de mots, position curseur, sync status, etc.

Trois modes d'édition :
  • SOURCE MODE : affichage brut du Markdown (idéal pour apprendre)
  • LIVE PREVIEW : rendu en temps réel tout en gardant l'édition (recommandé)
  • READING MODE : rendu final en lecture seule (pour lire)

Raccourci pour basculer : Ctrl/Cmd + E


8. WORKFLOW DES 30 PREMIÈRES MINUTES (D'après Optimike)
--------------------------------------------------------------------------------
  0-5 min  : Créer votre vault et une note d'accueil "Bienvenue"
  5-10 min : Écrire une vraie note sur un sujet concret vous concernant
  10-15 min: Créer trois liens internes [[Nom-de-note]] entre vos notes
  15-20 min: Ouvrir Backlinks et Vue graphique pour comprendre les relations
  20-30 min: Décider d'UNE action quotidienne (ex : une note par jour)

Règle d'or : NE PAS installer de plugins tant que vous n'avez pas produit
100 notes en Markdown vanilla. Vous découvrirez ainsi vos vrais besoins.

9. MARKDOWN DE BASE (Syntaxe officielle Obsidian)
--------------------------------------------------------------------------------
9.1 TITRES / EN-TÊTES
  # Titre niveau 1
  ## Titre niveau 2
  ### Titre niveau 3
  #### Titre niveau 4
  ##### Titre niveau 5
  ###### Titre niveau 6
  → Jusqu'à 6 niveaux avec le symbole #

9.2 EMPHASE (Gras, italique, surlignage, barré)
  **Texte en gras**                     ou __Texte en gras__
  *Texte en italique*                   ou _Texte en italique_
  ~~Texte barré~~
  ==Texte surligné==                    (spécifique Obsidian)
  ***Texte gras et italique***          ou ___Texte gras et italique___
  **Texte gras et _italique imbriqué_**

9.3 LISTES
  Non ordonnées :
    - Élément 1
    - Élément 2
      - Sous-élément (indentation 2 ou 4 espaces)
    * Autre syntaxe valide
    + Autre syntaxe valide

  Ordonnées :
    1. Premier élément
    2. Deuxième élément
    3. Troisième
    1) Syntaxe alternative

  Tâches (Task lists) :
    - [ ] Tâche non terminée
    - [x] Tâche terminée
    - [/] Tâche en cours (extension)
    - [-] Tâche annulée (extension)
    - [?] Tâche en question (extension)

9.4 CITATIONS
  > Ceci est une citation.
  > Elle peut s'étendre sur plusieurs lignes.
  >
  > > Et être imbriquée.

9.5 LIGNES HORIZONTALES
  ---
  ***
  ___
  (trois caractères ou plus sur une ligne isolée)

9.6 CODE
  Inline : `let x = 42;`

  Bloc avec langage :
    ```javascript
    function hello() {
      console.log("Hello Obsidian!");
    }
    ```

  Bloc avec tildes (alternative) :
    ~~~python
    def hello():
        print("Hello Obsidian!")
    ~~~

  Coloration syntaxique : Obsidian utilise Prism.js. Voir la liste des
  langages supportés sur https://prismjs.com/#supported-languages

9.7 LIENS EXTERNES
  [Texte du lien](https://exemple.com)
  [Texte avec titre](https://exemple.com "Titre au survol")
  <https://url-directe.com>            (autolink)

9.8 IMAGES EXTERNES
  ![Texte alternatif](https://exemple.com/image.jpg)
  ![|300](https://exemple.com/image.jpg)       (largeur 300px)
  ![|300x200](https://exemple.com/image.jpg)   (300x200)

9.9 NOTES DE BAS DE PAGE (Footnotes)
  Ceci est une phrase avec une note[^1].
  [^1]: Voici le contenu de la note de bas de page.

  Note en ligne :
  Ceci est une phrase^[avec une note en ligne].

9.10 COMMENTAIRES (invisibles au rendu)
  %% Ceci est un commentaire, visible uniquement en mode Source %%


10. SYNTAXE AVANCÉE — OBSIDIAN FLAVORED MARKDOWN (OFM)
--------------------------------------------------------------------------------
10.1 TABLEAUX
  | Colonne 1 | Colonne 2 | Colonne 3 |
  |-----------|-----------|-----------|
  | Cellule A | Cellule B | Cellule C |
  | Cellule D | Cellule E | Cellule F |

  Alignement (via les tirets) :
  | Gauche | Centre | Droite |
  |:-------|:------:|-------:|
  | A      |   B    |      C |

  Astuce : le plugin communautaire "Advanced Tables" facilite grandement
  l'édition (Tab/Shift-Tab pour naviguer, tri automatique, formules).

10.2 MATHÉMATIQUES LATEX (MathJax)
  Inline : $E = mc^2$

  Bloc :
  $$
  \int_{-\infty}^{\infty} e^{-x^2} dx = \sqrt{\pi}
  $$

  Support complet de LaTeX/MathJax : matrices, intégrales, sommes, fractions,
  symboles grecs, etc.

10.3 DIAGRAMMES MERMAID
  ```mermaid
  graph LR
    A[Idée] --> B[Note atomique]
    B --> C[MOC]
    C --> D[Article publié]
  ```

  Types supportés : flowchart, sequence, gantt, class, state, ER,
  user journey, pie chart, mindmap, timeline.

10.4 CALLOUTS (12 types officiels)
  Syntaxe générale :
    > [!type] Titre facultatif
    > Contenu du callout, peut s'étendre sur plusieurs lignes.
    > **Markdown** _fonctionne_ dedans.

  Ajouter `-` après le type pour un callout replié par défaut,
  ou `+` pour un callout déplié explicitement.

  Les 12 types officiels et leurs alias :

    > [!note]        (alias : default)
    > [!abstract]    (alias : summary, tldr)
    > [!info]
    > [!todo]
    > [!tip]         (alias : hint, important)
    > [!success]     (alias : check, done)
    > [!question]    (alias : help, faq)
    > [!warning]     (alias : caution, attention)
    > [!failure]     (alias : fail, missing)
    > [!danger]      (alias : error)
    > [!bug]
    > [!example]
    > [!quote]       (alias : cite)

  Exemples pratiques :
    > [!tip] Astuce importante
    > Utilisez toujours [[wikilinks]] pour créer les connexions du graphe.

    > [!warning]- Attention (replié)
    > Ne stockez pas vos vaults sur un dossier synchronisé par plusieurs clouds.

10.5 IDENTIFIANTS DE BLOC (Block references)
  Pour créer un lien vers un bloc spécifique :
    Contenu à référencer ^unique-id

  Puis on référence avec :
    [[Note#^unique-id]]        (lien simple)
    ![[Note#^unique-id]]       (embed du bloc)


11. LIENS INTERNES, WIKILINKS ET EMBEDS
--------------------------------------------------------------------------------
11.1 DEUX FORMATS DE LIENS INTERNES
  • Wikilink (recommandé Obsidian) :
      [[Nom de la note]]
      [[Nom de la note|Alias affiché]]

  • Markdown standard (interopérable) :
      [Nom de la note](Nom%20de%20la%20note.md)

  Pour choisir : Settings > Files & Links > "Use [[Wikilinks]]"
  Recommandation : wikilinks pour usage Obsidian pur ; markdown standard
  si vous prévoyez d'exporter vers d'autres outils (GitHub, Hugo, etc.).

11.2 LIENS VERS DES SECTIONS
  [[Note#Titre]]              → lien vers un titre
  [[Note#Titre#Sous-titre]]   → lien vers un sous-titre imbriqué
  [[Note#^blockID]]           → lien vers un bloc

11.3 LIENS INTERNES DANS LA MÊME NOTE
  [[#Titre-de-cette-note]]
  [[#^blockID]]

11.4 EMBEDS — INTÉGRATION DE CONTENU
  Syntaxe universelle : préfixer un lien interne par !

  Embed d'une note entière :
    ![[Note-à-intégrer]]

  Embed d'une section :
    ![[Note#Titre spécifique]]

  Embed d'un bloc :
    ![[Note#^blockID]]

  Embed d'une image du vault :
    ![[image.png]]
    ![[image.png|300]]        (largeur 300)
    ![[image.png|300x200]]    (dimensions précises)

  Embed d'un PDF :
    ![[document.pdf]]
    ![[document.pdf#page=3]]           (page 3 uniquement)
    ![[document.pdf#height=400]]       (hauteur 400px)

  Embed d'un fichier audio :
    ![[extrait.mp3]]
    ![[podcast.ogg]]

  Embed d'un canvas :
    ![[MonCanvas.canvas]]
    (Note : n'affiche que les formes, pas le texte des cartes)

  Embed d'une liste avec block reference :
    Dans la note source :
      - Élément 1
      - Élément 2
      ^ma-liste

    Dans la note cible :
      ![[Note-source#^ma-liste]]

  Astuce Desktop : glisser-déposer un fichier supporté directement dans
  une note l'intègre automatiquement.


12. CALLOUTS — DÉTAIL COMPLET
--------------------------------------------------------------------------------
Les callouts sont une extension d'Obsidian de la syntaxe blockquote.

Anatomie d'un callout :
  > [!TYPE]{modifier} Titre
  > Contenu ligne 1
  > Contenu ligne 2

Modificateurs :
  (rien)  → callout ouvert et fixe
  -       → callout replié (foldable, closed by default)
  +       → callout dépliable (foldable, open by default)

Callouts imbriqués :
  > [!note] Note parente
  > Contenu de la note.
  >
  > > [!tip] Astuce imbriquée
  > > Contenu de l'astuce.

Cas d'usage recommandés :
  • [!warning]  → alertes de sécurité, pièges à éviter
  • [!tip]      → astuces, raccourcis
  • [!example]  → exemples de code, cas concrets
  • [!quote]    → citations d'auteurs, extraits de livres
  • [!question] → FAQ, questions ouvertes à explorer
  • [!todo]     → actions à réaliser (complément à Tasks)

14. TAGS ET HIÉRARCHIE DE TAGS
--------------------------------------------------------------------------------
14.1 SYNTAXE
  Simple    : #idée #projet #lecture
  Imbriqué  : #projet/actif #projet/archive
              #ressource/livre #ressource/article #ressource/podcast

14.2 EMPLACEMENT
  • Dans le corps d'une note : # doit être précédé d'un espace ou début
    de ligne (sinon confondu avec un titre).
  • Dans le frontmatter YAML (recommandé) :
      ---
      tags:
        - projet/actif
        - lecture-en-cours
      ---

14.3 BONNES PRATIQUES
  • Un maximum de 2-3 tags par note (règle ps11.hashnode.dev)
  • Utiliser une hiérarchie cohérente #type/sous-type
  • Ne pas multiplier les tags sémantiquement proches (#idea vs #ideas)
  • Préférer les liens [[wikilinks]] aux tags pour les CONCEPTS
    (les tags servent au STATUT et à la NATURE)

14.4 CONVENTION RECOMMANDÉE
  #status/inbox     #status/wip      #status/done      #status/archive
  #type/idea        #type/note       #type/moc         #type/project
  #zone/perso       #zone/travail    #zone/apprentissage

15. IMAGES : INSERTION, ORGANISATION, REDIMENSIONNEMENT
--------------------------------------------------------------------------------
15.1 MÉTHODES D'INSERTION D'IMAGES
  a) GLISSER-DÉPOSER (recommandé)
     Faire glisser une image depuis l'explorateur système vers la note.
     Obsidian copie l'image dans le dossier d'attachements et insère
     automatiquement la syntaxe d'embed.

  b) COPIER-COLLER
     Copier une capture d'écran (Ctrl/Cmd+Shift+S, ou outil de capture)
     puis coller dans la note (Ctrl/Cmd+V). Obsidian génère un nom
     de fichier et copie l'image dans le dossier configuré.

  c) SYNTAXE MARKDOWN MANUELLE
     ![[image.png]]                   (wikilink, format Obsidian)
     ![Alt text](chemin/image.png)    (markdown standard)

  d) PLUGIN "Simple Image Inserter"
     Palette de commandes > "Insert image(s)" > sélectionner > "Open"

  e) BASE64 (déconseillé, alourdit la note)
     ![](data:image/png;base64,iVBORw0KGgo...)

15.2 CONFIGURER LE DOSSIER D'ATTACHEMENTS
  Chemin : Settings > Files & Links > "Default location for new attachments"

  Trois modes :
    1. Vault folder (racine du vault) — chaotique à long terme
    2. In the folder specified below — un dossier centralisé (recommandé)
    3. Same folder as current file — chaque note a ses images à côté
    4. In subfolder under current folder — sous-dossier par note

  Recommandation : créer un dossier "Attachments" ou "assets" à la racine
  et le définir comme dossier par défaut.

15.3 CHOISIR ENTRE WIKILINK ET MARKDOWN POUR LES IMAGES
  Settings > Files & Links > "Use [[Wikilinks]]" :
    • Activé  → ![[image.png]]                (portable seulement Obsidian)
    • Désactivé → ![alt](attachments/image.png) (compatible tout Markdown)

15.4 REDIMENSIONNER UNE IMAGE
  ![[image.png|400]]           → largeur 400px, hauteur auto
  ![[image.png|400x300]]       → 400x300 précis
  ![300](https://url/img.jpg)  → externe, largeur 300

15.5 REDIMENSIONNEMENT INTERACTIF
  En mode Reading, cliquez sur l'image puis glissez les coins.
  Obsidian met à jour la syntaxe dans la note.

15.6 ALIGNEMENT & MISE EN PAGE AVANCÉE (via HTML)
  <p align="center"><img src="image.png" width="400"></p>

15.7 BONNES PRATIQUES DE GESTION D'IMAGES
  • Nommer les images de manière descriptive : "obsidian-graph-vue-2026.png"
    et non "Screenshot_20260722_142302.png".
  • Compresser les images (TinyPNG, ImageOptim) avant de les ajouter.
  • Créer un dossier attachments par grande zone thématique si vous
    avez des milliers d'images.

    images (pas d'OCR natif). Utiliser un plugin comme Text Extractor

--------------------------------------------------------------------------------
16.1 INTÉGRER UN PDF DANS UNE NOTE
  ![[document.pdf]]                    (embed complet)

  ![[document.pdf#height=600]]         (hauteur 600px de la visionneuse)

16.2 WORKFLOW ACADÉMIQUE COMPLET (source : effortlessacademic.com)
  L'objectif : connecter TROIS éléments pour chaque lecture :
    1) L'annotation dans le PDF
    2) Un commentaire / conclusion personnel
    3) Une note de synthèse générale sur le document

  Cela crée des "deep links" (liens profonds) entre la source et vos idées.

16.3 ORGANISATION DES PDF
  • Dossier dédié : "__Papers/" ou "Bibliographie/"

      "Smith 2020 - Deep Learning Foundations.pdf"

  • PDF++ (recommandé) : édition directe du PDF, annotations incrustées,
    liens vers passages précis, copier-coller de liens contextuels.
    Courbe d'apprentissage plus élevée mais puissance maximale.
  • Annotator : alternative plus légère. Annotations stockées dans des

  b) Application externe (macOS) : PDF Search

  c) Zotero 7 : Advanced Search > Attachment Content

16.6 EXPORTER UNE NOTE OBSIDIAN EN PDF
  Menu > Export to PDF
  Options : marges, mode d'impression (édition/lecture), taille de page,
  échelle, images incluses.


17. PIÈCES JOINTES ET DOSSIER ATTACHMENTS
--------------------------------------------------------------------------------
17.1 PRINCIPE FONDAMENTAL D'OBSIDIAN
  Obsidian ne "colle" pas les images/PDF/audio DANS la note (comme Word).
  Il stocke le fichier séparément dans le vault et affiche un lien
  d'embed. Ceci garantit :
    • Portabilité (un fichier, un rôle)
    • Réutilisation (une image dans plusieurs notes)
    • Performance (les notes Markdown restent légères)

17.2 STRUCTURE RECOMMANDÉE
  Vault/
    ├── Attachments/
    │   ├── Images/
    │   ├── PDF/
    │   ├── Audio/
    │   └── Video/
    ├── Notes/
    └── ...

17.3 CONFIGURATION UNIQUE OU PAR SOUS-DOSSIER
  Settings > Files & Links > Default location for new attachments :
    • "In the folder specified below" → mettre "Attachments"
    • Cela s'applique à toutes les images collées / glissées / capturées.

22. NOTES ATOMIQUES (ATOMIC NOTES)
--------------------------------------------------------------------------------
Une note atomique respecte trois principes (héritage Zettelkasten) :

  1. UNE SEULE IDÉE PAR NOTE
     Si une note contient deux idées distinctes, la scinder.

  2. AUTONOMIE
     La note doit être compréhensible hors de son contexte original.
     Un futur vous, dans 5 ans, sans mémoire du sujet, doit pouvoir la lire.

  3. LIÉE
     Chaque note doit pointer vers au moins UNE autre note pertinente
     (règle Matt Giaro : "link to at least ONE related note").

Anti-exemples de notes atomiques :
  ✗ Une note "Lecture du 22 juillet" contenant 12 idées différentes
  ✗ Un chapitre entier de livre recopié dans une seule note
  ✗ Une note qui ne fait référence à aucune autre

Bons exemples :
  ✓ "La règle des 3H de Cal Newport"
  ✓ "Pourquoi Obsidian utilise le format .md"
  ✓ "Effet Zeigarnik en gestion de tâches"

23. LES 6 TYPES DE PROPRIÉTÉS OBSIDIAN
--------------------------------------------------------------------------------
Les Properties (anciennement Frontmatter YAML) sont des métadonnées
clé-valeur placées en haut d'une note, entre deux lignes ---.

Emplacement obligatoire :
  ---
  cle1: valeur1
  cle2: valeur2
  ---
  # Contenu de la note commence ici

Les 6 types disponibles :

23.1 TEXT (défaut)
  Une ligne de texte. Supporte liens internes et externes.
    title: "Ma note importante"
    author: "[[John Doe]]"

23.2 LIST
  Plusieurs valeurs (une par ligne préfixée par un tiret).
    tags:
      - projet/actif
      - lecture-en-cours
    keywords:
      - PKM
      - second-cerveau

23.3 NUMBER
  Nombres entiers ou décimaux uniquement (pas d'opérations).
    rating: 4.5
    word_count: 1234

23.4 CHECKBOX
  Booléen (true/false) affiché comme case à cocher en mode Live/Reading.
    completed: true
    published: false

23.5 DATE
  Format ISO : YYYY-MM-DD. Lien automatique vers Daily Notes si activé.
    due: 2026-08-15
    started: 2026-07-01

23.6 DATE & TIME
  Format ISO complet : YYYY-MM-DDTHH:MM:SS.
    meeting_at: 2026-07-25T14:30:00
    reviewed: 2026-07-22T09:15:00

23.7 PROPRIÉTÉS PAR DÉFAUT (built-in)
  • tags       (list) — tags de la note
  • aliases    (list) — noms alternatifs pour les [[wikilinks]]
  • cssclasses (list) — classes CSS à appliquer à la note


24. BONNES PRATIQUES DE NOMMAGE YAML
--------------------------------------------------------------------------------
D'après le guide practicalpkm.com :

24.1 RÈGLES FONDAMENTALES
  1. COHÉRENCE — Utiliser toujours la même propriété de la même façon.
     Ex : ne pas alterner "author" et "auteur" dans deux notes différentes.

  2. SPÉCIFICITÉ — Si deux workflows diffèrent, préférer deux propriétés :
     Ex : "video_status" et "newsletter_status" (au lieu d'un "status" ambigu).

  3. PARCIMONIE — N'ajouter une propriété que si elle sert réellement
     à filtrer, trier ou requêter (Dataview/Bases).

24.2 CONVENTIONS DE NOMMAGE
  ✓ Singulier par défaut : "tag" plutôt que "tags" (sauf built-in)
                            "rating" plutôt que "ratings"
  ✓ Pas d'espaces          : "due_date" (pas "due date")
  ✓ Snake_case             : "publication_date", "read_status"
  ✓ Autocomplete           : profiter des suggestions pour éviter les typos

24.3 TEMPLATE DE FRONTMATTER TYPE
  Pour une note de lecture :
    ---
    type: book-note
    title: Building a Second Brain
    author: Tiago Forte
    year: 2022
    isbn: 978-1982167387
    rating: 4
    status: finished
    started: 2026-06-01
    finished: 2026-06-25
    tags:
      - lecture/livre
      - domaine/productivite
    aliases:
      - BASB
      - Second Brain
    ---

26. MÉTHODE PARA (Tiago Forte)
--------------------------------------------------------------------------------
PARA = Projects, Areas, Resources, Archives

Principe cardinal : organiser par ACTIONNABILITÉ (pas par sujet).

26.1 LES QUATRE CATÉGORIES

  P — PROJECTS (Projets)
    Objectifs à court terme avec deadline et livrable clair.
    Exemples : "Lancer newsletter", "Écrire article X", "Voyage Japon"
    Question-test : "Est-ce que ce projet a une date de fin ?"

  A — AREAS (Domaines de responsabilité)
    Zones de vie à maintenir en continu, sans deadline.
    Exemples : Santé, Finances, Famille, Carrière
    Question-test : "Est-ce une responsabilité permanente ?"

  R — RESOURCES (Ressources)
    Sujets d'intérêt, références potentiellement utiles.
    Exemples : Livres, articles, tutoriels, citations, idées
    Question-test : "Cela pourrait m'être utile un jour ?"

  A — ARCHIVES (Archives)
    Éléments terminés ou dormants (mais potentiellement réactivables).
    Exemples : Projets clos, anciens jobs, notes obsolètes
    Question-test : "Ai-je fini d'utiliser ceci mais pourrais-je y revenir ?"

26.2 STRUCTURE DE VAULT PARA
  Second-Brain/
    ├── 1-Projects/
    │   ├── Lancement newsletter/
    │   └── Article second cerveau/
    ├── 2-Areas/
    │   ├── Santé/
    │   ├── Finances/
    │   └── Carrière/
    ├── 3-Resources/
    │   ├── Livres/
    │   ├── Articles/
    │   └── Idées/
    └── 4-Archives/
        └── 2025/

26.3 WORKFLOW HEBDOMADAIRE PARA
  Chaque semaine, ~30 min :
    1. Déplacer les Projects terminés vers Archives
    2. Repromouvoir des Resources en Projects si un projet actif les concerne
    3. Rétrograder les Areas inactives vers Archives
    4. Réordonner les priorités

26.4 CRITIQUE DE PARA POUR OBSIDIAN
  Matt Giaro (mattgiaro.com) argumente que PARA fonctionne bien pour la
  GESTION DE PROJETS mais mal pour la PENSÉE CRÉATIVE dans Obsidian, où
  la force réside dans les liens et non dans les dossiers.


27. MÉTHODE ZETTELKASTEN (Niklas Luhmann)
--------------------------------------------------------------------------------
Zettelkasten = "boîte à fiches" (allemand). Système développé par le
sociologue Niklas Luhmann, auteur de 70+ livres grâce à sa méthode.

27.1 LES TROIS TYPES DE NOTES
  a) FLEETING NOTES (notes éphémères)
     Captures immédiates : idées à la volée, notes de conférence brouillonnes.
     Traitement : lues dans les 48h puis converties ou supprimées.

  b) LITERATURE NOTES (notes de lecture)
     Résumés dans vos propres mots des sources lues (livres, articles).
     Doivent inclure la référence exacte (page, chapitre).

  c) PERMANENT NOTES (notes permanentes / evergreen)
     Idées formulées avec précision, autonomes, atomiques.
     Le cœur de votre Zettelkasten. Elles doivent être :
       • Atomiques  (une idée)
       • Autonomes  (compréhensibles seules)
       • Connectées (liées à d'autres permanent notes)

27.2 LES 4 PRINCIPES CARDINAUX DE LUHMANN
  1. Écrire avec ses propres mots (pas de copier-coller)
  2. Créer des liens explicites entre notes
  3. Ne pas classer prématurément (laisser la structure émerger)
  4. Développer un index thématique évolutif

27.3 IMPLÉMENTATION DANS OBSIDIAN
  Vault/
    ├── 0-Inbox/            (fleeting notes)
    ├── 1-Literature/       (literature notes)
    ├── 2-Permanent/        (permanent notes = Zettel)
    ├── 3-MOC/              (Maps of Content = index thématiques)
    └── 4-Templates/


28. MOC — MAPS OF CONTENT (Nick Milo)
--------------------------------------------------------------------------------
Un MOC est une note dont le rôle principal est de LIER d'autres notes,
créant un index / table des matières pour un domaine.

28.1 QUAND CRÉER UN MOC ?
  • Quand vous avez 5+ notes sur un même thème
  • Quand vous vous perdez à retrouver vos idées sur un sujet
  • Comme point d'entrée dans un domaine complexe

28.2 STRUCTURE TYPE D'UN MOC
  # MOC — Second Cerveau

  > Cartographie des idées liées à la construction d'un second cerveau
  > dans Obsidian.

  ## Concepts fondamentaux
  - [[Notes atomiques]]
  - [[Backlink et lien bidirectionnel]]
  - [[Vault et structure]]

  ## Méthodologies
  - [[Méthode PARA]]
  - [[Zettelkasten]]
  - [[Progressive Summarization]]

  ## Plugins essentiels
  - [[Dataview - guide]]
  - [[Templater - guide]]

  ## Workflows quotidiens
  - [[Capture rapide sur mobile]]
  - [[Revue hebdomadaire]]

  ## Notes en attente de tri
  ```dataview
  list from [[]] and !outgoing([[]])
  ```

28.3 REQUÊTE DATAVIEW POUR MOC AUTO-ALIMENTÉ
  ```dataview
  list from [[]] and !outgoing([[]])
  ```
  Cette requête liste toutes les notes qui référencent le MOC courant
  MAIS que le MOC n'a pas encore explicitement organisées. Elle sert
  d'inbox de tri.

28.4 EMBOÎTEMENT DE MOC
  On peut créer des MOC de MOC (méta-MOC). Exemple :
    [[Home]] → [[MOC - Personnel]] → [[MOC - Santé]] → notes
                                  → [[MOC - Finances]] → notes


29. APPROCHE MINIMALISTE "ZÉRO DOSSIER" (Matt Giaro)
--------------------------------------------------------------------------------
Philosophie radicale : abandonner totalement les dossiers, utiliser
UNIQUEMENT les liens et les tags.

Matt Giaro rapporte 4 819 notes dans Obsidian, ZÉRO dossier.

29.1 JUSTIFICATION
  • Les dossiers créent une hiérarchie rigide qui limite les connexions
  • Une note appartient souvent à plusieurs contextes (multi-parentalité)
  • Le graph et les backlinks font émerger la structure naturellement
  • Moins de friction : "où ranger cette note ?" disparaît

29.2 WORKFLOW MINIMALISTE
  1. CAPTURE (externe à Obsidian pour la fluidité)
     Voix   → Letterly (transcription) → Bear (bucket d'idées)
     Texte  → Bear (avec Apple shortcut)

  2. TRAITEMENT (dans Obsidian, quand l'humeur y est)
     • Piocher 5-10 idées de Bear qui excitent
     • Les déplacer dans Obsidian
     • Les réécrire dans ses propres mots (Feynman)
     • Lier à AU MOINS une note existante

  3. CRÉATION
     • Ouvrir plusieurs panneaux de notes liées
     • Assembler des insights existants (pas partir de zéro)
     • Ex : article rédigé en 37 min en assemblant 12+8+3+4 notes

29.3 PLUGINS MINIMAUX DE MATT GIARO
  • Projects (calendrier éditorial)
  • Canvas (planification visuelle)
  • Graph View (découverte de connexions)

29.4 AVERTISSEMENT
  Cette approche fonctionne SI :
    • Vous liez rigoureusement chaque nouvelle note
    • Vous acceptez de fouiller via recherche + graphe
    • Vous ne mélangez pas vie perso et pro dans le même vault

36. DATAVIEW : REQUÊTES DQL
--------------------------------------------------------------------------------
Dataview transforme votre vault en base de données requêtable.

36.1 STRUCTURE GÉNÉRALE D'UNE REQUÊTE

  ```dataview
  <QUERY-TYPE> <fields>
  FROM <source>
  <DATA-COMMAND> <expression>
  <DATA-COMMAND> <expression>
  ...
  ```

36.2 LES 4 QUERY TYPES
  • TABLE     — tableau avec colonnes personnalisées
  • LIST      — liste à puces des notes
  • TASK      — tâches interactives
  • CALENDAR  — vue calendrier (un point par date)

36.3 SOURCES (clause FROM)
  FROM "Dossier"                       → un dossier
  FROM #tag                            → un tag
  FROM #tag1 AND #tag2                 → ET logique
  FROM #tag1 OR #tag2                  → OU logique
  FROM [[Note]]                        → notes qui pointent vers Note
  FROM outgoing([[Note]])              → notes vers lesquelles Note pointe

36.4 DATA COMMANDS
  WHERE <expression>          → filtre sur métadonnées
  SORT <field> ASC/DESC       → tri
  GROUP BY <field>            → regroupement
  LIMIT <n>                   → nombre max de résultats
  FLATTEN <field>             → une ligne par valeur d'un champ liste

36.5 EXEMPLES CONCRETS

  Toutes les notes en cours de lecture, triées par date :
    ```dataview
    TABLE author, rating
    FROM #lecture
    WHERE status = "reading"
    SORT started DESC
    ```

  Toutes les tâches ouvertes, groupées par fichier :
    ```dataview
    TASK
    WHERE !completed
    GROUP BY file.link
    SORT file.mtime DESC
    ```

  Notes créées cette semaine :
    ```dataview
    LIST
    FROM ""
    WHERE file.cday >= date(today) - dur(7 days)
    SORT file.ctime DESC
    ```

  Projets actifs avec échéance imminente :
    ```dataview
    TABLE status, due, priority
    FROM "1-Projects"
    WHERE status = "active" AND due <= date(today) + dur(14 days)
    SORT due ASC
    ```

  Calendrier des dates d'échéance :
    ```dataview
    CALENDAR due
    FROM "1-Projects"
    WHERE due
    ```

36.6 INLINE DATAVIEW (dans le corps d'une note)
  Nombre de notes dans mon vault : `= length(file.lists)`
  Aujourd'hui = `= date(today)`
  Mon rating moyen : `= round(average(file.rating), 2)`

36.7 DATAVIEW JS (JavaScript avancé)
  ```dataviewjs
  const pages = dv.pages('"1-Projects"')
    .where(p => p.status === "active")
    .sort(p => p.due);
  dv.table(["Nom","Due"], pages.map(p => [p.file.link, p.due]));
  ```

50. LIMITATIONS CONNUES D'OBSIDIAN
--------------------------------------------------------------------------------
50.1 COLLABORATION TEMPS RÉEL
  Obsidian n'est PAS conçu pour l'édition simultanée (contrairement à
  Notion, Google Docs). Solutions partielles : Git avec branches et PRs.

50.2 EXCEL / TABLEURS
  Obsidian ne gère pas les .xlsx. Les tableaux Markdown sont pratiques
  mais limités (pas de formules natives, pas de tri par colonne sans
  plugin). Alternative : plugin Advanced Tables + Bases.

50.3 RECHERCHE DANS PDF NATIVE
  La recherche full-text native ne fouille PAS le contenu des PDF.
  Solution : plugin Text Extractor + Omnisearch.

50.4 OCR DES IMAGES
  Aucune reconnaissance de texte native dans les images.
  Solution : Text Extractor (OCR) ou tesseract externe.

50.5 MOBILE : PLUGINS LIMITÉS
  Sur iOS/Android, tous les plugins ne fonctionnent pas.
  Vérifier la mention "Mobile compatible" sur chaque plugin.

50.6 GROS VAULTS (>50 000 notes)
  Performances dégradées possibles. Solutions :
    • Vaults multiples par grand contexte
    • Désactiver les plugins non essentiels
    • Optimiser les requêtes Dataview (FROM restrictif)

50.7 EXPORTS
  Export PDF correct mais limité en styling avancé.
  Export DOCX, EPUB : uniquement via plugins tiers (Pandoc, etc.).

50.8 SYNC DE FICHIERS BINAIRES VOLUMINEUX
  Obsidian Sync a des limites par fichier (~4 Mo par défaut).
  Pour les gros PDF, préférer stockage cloud externe + lien.


51. ANTI-PATTERNS FRÉQUENTS
--------------------------------------------------------------------------------
❌ 1. Créer 50 dossiers avant d'écrire 10 notes.
     → Commencer plat, structurer après.

❌ 2. Installer 30 plugins dès le premier jour.
     → Vanilla d'abord, plugin quand un besoin réel émerge.

❌ 3. Tagger chaque note avec 15 tags.
     → 1-3 tags maximum, hiérarchisés.

❌ 4. Copier-coller des articles entiers dans ses notes.
     → Réécrire dans ses propres mots (technique Feynman).

❌ 5. Ne jamais relier ses notes.
     → Règle : chaque nouvelle note doit lier ≥ 1 existante.

❌ 6. Sauter la revue hebdomadaire.
     → 15 min/semaine pour trier l'Inbox et actualiser MOC.

❌ 7. Confondre "vault" et "backup".
     → Le vault n'est PAS une sauvegarde. Implémenter le 3-2-1.

❌ 8. Utiliser Obsidian comme éditeur de fichiers Word.
     → Le format .md est le format, pas un obstacle.

❌ 9. Reporter la création d'une note pour "faire mieux plus tard".
     → 80% mal fait > 100% jamais fait.

❌ 10. Perfectionner la structure au lieu de produire du contenu.
      → "Build a system that adapts to you, not you to it." (Matt Giaro)

  • Prompt library partagée par la communauté

53.3 NOVA
  • Édition inline sans quitter la note
  • Transformations : traduire, résumer, expliquer, corriger, reformuler
  • Streaming du remplacement en temps réel

53.4 SMART SECOND BRAIN (100% local)
  • Backend Ollama
  • Modèles recommandés 2026 : Qwen2.5, Llama 3.3, Phi-4
  • Compromis : moins puissant qu'un cloud, mais confidentiel


54. INTÉGRATION CLAUDE CODE / MCP
--------------------------------------------------------------------------------
Le développement majeur de 2026 : connecter Claude Code (agent CLI
d'Anthropic) à Obsidian via MCP (Model Context Protocol).

54.1 CE QUE ÇA PERMET
  Votre vault devient un espace de travail vivant que Claude peut :
    • Lire (recherche sémantique dans vos notes)
    • Modifier (édition d'une note existante)
    • Créer (nouvelles notes structurées)
    • Réorganiser (renommer, déplacer, lier)

54.2 CAS D'USAGE
  • Revue hebdomadaire : "Claude, résume les notes créées cette semaine"
  • Synthèse de recherche : "Trouve les patterns communs aux notes taguées
    #recherche/machine-learning"
  • Préparation de meeting : "Récupère les décisions liées à Projet Alpha
    depuis 3 mois"
  • Documentation code : lier automatiquement le code aux ADR

  □ Créer un template de journalisation quotidienne
  □ Journaliser 7 jours d'affilée

  □ Créer un dashboard de projets

  □ Créer un dashboard de tâches

  □ Mettre en place la règle 3-2-1
  □ Tester une restauration

SEMAINE 12 — Personnalisation et IA
  □ Choisir un thème et 1-2 snippets CSS
  □ Installer Smart Connections (ou équivalent local)

  □ Réviser toutes les notes, consolider les MOC
